# 可靠性、统计性能与设置页验收

日期：2026-10-11。对应「清理可靠性 → 分页一致性 → 抖音回归 → 容量与查询性能 → 交互反馈、架构和文档」计划。没有新增后端、自动清理、IndexedDB、依赖或权限；没有执行 Git 提交、推送。

## 已实现的行为

- 清理先持久化操作 ID、阶段、待删键和保留 ID，再重写索引、分批删除并读回核验；不在任务中复制正文。任务保存失败不开始删除。后台启动、后续写入和手动重试会恢复任务，恢复结束前不追加新事件。
- 无筛选清空同时检查已知 V1/V2 命名空间，删除孤立事件、索引块和备份；保留收藏、日志与未知版本数据。读取期间遇到任务显示「正在清理」。
- 分页游标携带持久化 revision，删除或重排后过期；追加不失效。查询前后核对 revision。设置页遇到另一页清理时回到第一页并提示，不继续使用旧位置。
- 统计占用与 local 总占用使用浏览器容量接口，80%／95% 提醒，未知显示「暂不可用」。30／90／180 天前记录由用户确认后清理，日期以 UTC 为准，历史默认保留。
- 日汇总每批最多读取 128 天；设置页缓存随存储变化失效。正文搜索、导出分块读取，提供实际扫描进度和取消；清理提交后继续至完成或可恢复失败。
- UI 导出按日生成 JSON Blob 分段，保留既有字段和排序，避免整个历史对象与完整 JSON 字符串同时驻留。单日内容仍需要排序，极端集中在一天的历史会有较高峰值，尚未引入流式外部排序。
- 抖音原生设置提供应用状态、重试和关闭；累计 5 秒可见探测仍失败才显示一条提示，成功静默，同房间和设置组合不重复弹出。提示沿用现有浮层，不加阴影、不抢焦点，发送反馈出现时优先展示发送反馈。
- 三平台富表情元数据与资源归一化提取到 `rich-emoji-metadata.ts`，平台差异通过 adapter 注入。保留 token 顺序、身份、文字表示与回退优先级，没有改变发送流程。
- 中英文设置辅助文案同步缩短，自动缩放说明按计划统一；保留自动发送默认关闭、本地存储、UTC、不可撤销删除和关闭抖音自动设置不会恢复原状态的说明。增加窄窗口布局，正常宽度布局与缩放算法保持原样。

## 原始抖音 12 项失败逐项归因

基线：`test-results/reliability/douyin-before/`。保留原始失败产物；没有通过删除断言获得通过。

| 原断言 | 证据与归因 | 当前覆盖 |
| --- | --- | --- |
| `actionBehindMessage` | 预期过时，胶囊按可用空间左右选择，不固定在右侧 | `actionBesideMessage` 校验左右几何关系、不遮挡正文 |
| `actionGapReserved` | 旧间隙公式只支持右侧 | 对实际显示一侧计算间隙并检查边界 |
| `gapHoverKeptPaused` | 夹具使用旧胶囊位置移动指针 | 按当前几何位置进入间隙，验证停顿连续 |
| `favoriteRichAssetsRejected` | 预期过时且暴露产品缺陷：可用官方文字发送的表情仍应完整收藏；原分发器错误地复用发送用 payload | 改为 `favoriteRichAssetsPreserved`；分发器保存恢复后的完整 payload，验证 parts、assets、顺序及收藏显示；单测证明文字发送路径仍保留 |
| `replyPrefilled` | 连续操作后使用过时 hover 坐标，且缺失官方表情 alt 信息 | 重新悬停当前消息后验证完整 `@发送者 ` |
| `replyInputFocused` | 同上，回复动作未命中 | 验证官方编辑器获得焦点 |
| `replySurfaceCorrect` | 同上；全屏后续夹具还发现仅 MAIN world 的 fullscreen stub 对隔离世界不可见 | 抖音使用用户手势的真实 `requestFullscreen`，分别验证侧聊与全屏编辑器 |
| `clickSentMatchingMessage` | 夹具缺少 `[微笑]` 官方 token，echo 混排还重复拼接文字 | 补齐官方元数据并分开 text/image echo，核对官方输入捕获值和消息身份 |
| `ownMessageFramed` | 检查了内部文字节点，实际边框位于外层 barrage | 检查外层本人消息样式，同时保留本人消息匹配断言 |
| `canvasRestoredAfterDisable` | 夹具发送不存在的设置消息，没有真正禁用扩展 | 通过 `chrome.storage.sync` 真实设置链路禁用，检查原生 Canvas 恢复 |
| `layerInactiveAfterDisable` | 同上 | 同时检查扩展层停用及恢复后不重复挂载 |
| `sendStatisticsRecorded` | 前置发送夹具失败的连带结果 | 核对本次匹配发送的平台／房间／秒级时间／纯文本已写入统计 |

后续验证还修正了虎牙和 B 站测试的旧提示文案，以及斗鱼全屏夹具的发送捕获字段。发送结果、资源身份、输入内容、统计落盘等实质检查仍保留。

## 自动化检查与证据

- `npm run check`：113 个文件、660 项 Vitest 测试通过；覆盖率门槛通过；137 项契约测试通过。日志保存在 `test-results/reliability/check-final.log`。
- 清理单测在任务保存、索引更新、分批删除、收尾注入失败，再以新 store 实例恢复；包含第一批 128 个键已删除、第二批失败的情况，核对正文与真实 V1 迁移备份删除、恢复后新写入不被误删、未知 schema 和无关数据保留。
- 分页单测覆盖普通追加、旧游标、跨 UTC 日稀疏筛选、查询中清理、跨 reader/writer 清理；设置组件验证过期后回第一页。V1/V2 混合导出与旧对象 API 的 JSON 对照保留缺失字段语义。
- 300 天汇总的 cold/cache/invalidate 读取调用数为 7／2／7；搜索和导出在块边界取消不修改存储。V1 内存数组在块间让出执行时间，取消事件可实际中断；跨日及平台筛选的进度总量有独立测试。
- 富表情提取以迁移前实现生成的 27 个等价快照约束；涵盖通用属性优先级、三平台身份、边界和回退。
- 浏览器使用独立临时 profile、本地模拟站点和本次构建：Linux、Node 22.23.1、Chrome 155.0.8059.39、Edge 154.0.4258.62。浏览器 E2E 继续为本地可选项，未加入 CI。
- `final-browser/summary.json` 保留首轮已完成场景及失败项，上次执行在 Edge 后半段中断；后续 `verified-*` 独立目录保存修正后的场景与补齐结果，不覆盖旧失败证据。

## 验收范围限制

所有发送验证均在脱敏模拟页面上完成，没有使用真实账号发送。它们不能证明当前真实直播网站 DOM、账号表情权限、风控或实际消息送达。真实直播间清单仍保留待验，不将本轮结果用于勾选 F-05 的真实站点项目。

容量基准是当前实现的测量，不是改前改后的速度比较。`performance.memory` 是近似 JavaScript 堆采样，不含浏览器原生 Blob 和存储缓冲区，不代表整页总内存或操作系统进程峰值。

## 最终浏览器汇总

Chrome 与 Edge 各 30 项常规场景通过，另各通过 1 项统计容量基准，共 62 个 browser/scenario 组合。分批执行，汇总清单为 `test-results/reliability/verified-summary.json`，每项携带源报告路径；不将首轮中断的整套命令描述为单次全通过。修正后的最终场景均在 attempt 1 通过。

- 抖音覆盖侧聊、全屏、首次进房、SPA 切房、禁用/恢复、原生净化设置与异常重试。
- B 站、斗鱼、虎牙覆盖文字、平台图片表情、富消息、回复、收藏及全屏；富元数据等价性另有快照测试。
- 中英文页面覆盖 420px 有效宽度，以及 840px 窗口、浏览器 200% 缩放；无整页横向溢出，统计按钮文字完整。实际导出按钮生成的 Blob 已回读并与后台兼容导出对照。
- 双设置页测试：61 条记录下，A 翻到第二页，B 筛选并删除 1 条；A 自动回到第一页，显示 60 条汇总、正确的前 50 条和重新加载提示。中文证据在 `multi-page-settings-zh/`，英文 Chrome 在 `multi-page-settings-en/`，英文 Edge 在 `final-settings-en/`。
- 双页面夹具初版在第二页导航期间持有旧 JS execution context，运行器自动重试仍失败；已改成有界、逐次读取的就绪探测后复测。旧 `final-settings-zh/` 和英文 Chrome 失败报告保留，该失败不属于产品发送或存储缺陷。

## 最终统计容量基准

命令：`npm run test:browser -- --browser=all --scenario=statistics-performance --artifact-root=test-results/reliability/statistics-final`。每个浏览器使用独立一次性 profile，依次运行三种负载，每种负载前清空测试存储。使用真实 `chrome.storage.local` 与同一 store 源码；基准 bundle 仅留在产物目录，不进入扩展。每种负载分布在 10 个 UTC 日；普通数据正文约 100 字符，接近配额时增加正文长度至 10,063,960 / 10,485,760 bytes。

耗时单位 ms，一次测量，包含存储 IPC；「下一页」包含缓存汇总调用。正文查询使用不存在的关键词，扫描全量；导出核对 JSON 回读条数和秒汇总；清理核对事件、块、恢复任务结束及无关收藏保留。

| Chrome | 1,000 条 | 3.4 | 5.7 | 6.9 | 22.8 | 29.9 | 44.2 |
| Chrome | 10,000 条 | 2.6 | 3.9 | 3.2 | 192.2 | 246.3 | 377.9 |
| Chrome | 10,000 条，95.98% 配额 | 1.9 | 4.2 | 2.4 | 134.0 | 179.5 | 248.4 |

每 10ms 与扫描进度点采样；完整前后值保存在 JSON。未在操作之间强制 GC，堆包含夹具准备、导出回读及尚未回收的先前对象，因此表中是采样绝对值，不能当作模块净增内存或前后优化收益。近配额运行因预热和 GC 时机不同可以比前一档更快，不能由单次耗时推出规模越大越快。原生 Blob、浏览器存储缓冲及整个进程峰值未计入。

96% 配额下恢复任务可以保存且清理完成；任务键按前缀合并减少元数据占用。完全满额时仍可能无法保存恢复任务，此时保留原数据并报告失败，不为强行清理而跳过恢复保护。
